# Đánh giá Code: Licorp_MergeSheets (AutoCAD Plugin)

## Tổng quan Dự án

Plugin AutoCAD .NET để gộp nhiều file DWG thành một file duy nhất với 3 chế độ:
- **MultiLayout**: Mỗi file → 1 Layout tab riêng biệt
- **SingleLayout**: Gộp tất cả PaperSpace vào 1 layout
- **ModelSpace**: Gộp tất cả vào ModelSpace

**Stack**: C# / .NET 4.8 + .NET 8.0 / AutoCAD.NET SDK / Newtonsoft.Json

---

## 1. KIẾN TRÚC & CẤU TRÚC (Architecture)

### 1.1 Ưu điểm

- **Tách biệt rõ ràng**: `Commands.cs` (entry point), `LayoutMerger.cs` (core logic), `Models.cs` (data models), `AcadLogger.cs` (logging), `ExtentsHelper.cs` (utility), `Plugin.cs` (AutoCAD registration)
- **Implementation plan tốt**: `implementation_plan.md` mô tả chi tiết phương án 2 giai đoạn (ModelSpace trước → Layout sau), giải quyết triệt để vấn đề trùng lặp block
- **Hỗ trợ đa nền tảng**: `net48` + `net8.0-windows` trong cùng csproj
- **Logging toàn diện**: Ghi log ra Editor, DebugView (Win32), và file — rất hữu ích cho debug production

### 1.2 Vấn đề

#### 🔴 CRITICAL: File quá lớn — 5168 dòng trong 1 class

`LayoutMerger.cs` chứa **toàn bộ logic** trong một class duy nhất. Vi phạm nghiêm trọng **Single Responsibility Principle**.

**Đề xuất tách:**
```
LayoutMerger.cs (5168 lines) →
├── LayoutMerger.cs           (~300 lines)  — orchestration only
├── ModelSpaceCloner.cs       (~400 lines)  — MS clone + offset logic
├── PaperSpaceCloner.cs       (~500 lines)  — PS clone + layout creation
├── ViewportManager.cs        (~600 lines)  — viewport recreation/fix/bake
├── ExtentsCalculator.cs      (~400 lines)  — all extents/bounds logic
├── PlotSettingsManager.cs    (~300 lines)  — plot settings + media cache
├── PaperBackgroundManager.cs (~200 lines)  — background hatch/layer
├── PostProcessor.cs          (~200 lines)  — purge, cleanup, regen
├── RasterImageHandler.cs     (~100 lines)  — raster scan/copy
└── DstFileWriter.cs          (~80 lines)   — DST/JSON index generation
```

#### 🔴 CRITICAL: God Method — `MergeToMultiLayout` (~500 dòng)

Method `MergeToMultiLayout` (lines 136-629) xử lý **quá nhiều thứ**: mở file, bind xref, clone model space, tạo layout, clone paper space, fix viewport, bake, verify, save. Cần tách thành các method con có tên có ý nghĩa.

#### 🟡 Static mutable state

```csharp
private static string _cachedPlotDevice = null;          // line 31
private static List<string> _cachedCanonicalMedia = null; // line 59
private static DateTime _cachedMediaAt = DateTime.MinValue; // line 60
private static Dictionary<string, Tuple<double, double>> _mediaSizeCache = ...; // line 1832
```

Các static fields này **share state giữa các instance** và **không thread-safe**. Trong môi trường AutoCAD command có thể chạy lại, cache cũ sẽ stale. Nên chuyển thành instance fields hoặc dùng `Lazy<T>` / `ConcurrentDictionary`.

## 3. PERFORMANCE

### 3.1 Ưu điểm

- **Extents cache**: Tránh tính toán lại geometric extents cho cùng entity
- **Media size cache**: Cache kết quả `SetCanonicalMediaName` để không gọi PSV nhiều lần
- **Batch clone**: Dùng `WblockCloneObjects` thay vì clone từng entity

### 3.2 Vấn đề

#### 🟡 Multiple enumeration of BTR

Nhiều method iterate qua cùng BTR nhiều lần:
- `CollectModelViewportInfos` iterate 2 lần (1 cho raw, 1 cho usable)
- `GetPaperEntityExtentsExcludingViewports` iterate 1 lần
- `EraseAllLayoutViewports` iterate 1 lần để collect, 1 lần để erase

**Đề xuất**: Gộp thành single pass khi có thể.

#### 🟡 Unnecessary database open for verification

`VerifyCombinedFile` (line 988) mở lại file đã save chỉ để verify. Điều này đúng về mặt an toàn nhưng tốn I/O. Có thể verify ngay trong `outputDb` trước khi save.

#### 🟡 PostSaveRegen approach

`SchedulePostSaveRegen` (line 637) dùng `Application.Idle` event để mở file lại, gửi `REGENALL` + `QSAVE`. Đây là **workaround** cho crash khi gọi `DocumentManager.Open` trong command context. Cách này:
- Có thể conflict với user interaction
- Không đảm bảo thứ tự thực thi
- Có thể leak event handler nếu exception

## 4. RELIABILITY & ERROR HANDLING

### 4.1 Ưu điểm

- **Graceful degradation**: File layout đơn lỗi không crash toàn bộ merge
- **Retry logic**: `EnsurePendingScheduleOnlyLayouts` — layout tạo fail sẽ thử lại
- **Verification post-save**: Kiểm tra output sau khi lưu

### 4.2 Vấn đề

#### 🔴 Transaction management

Một số chỗ mở **2 transaction cùng lúc** trên 2 database khác nhau:
```csharp
using (var srcTrans = sourceDb.TransactionManager.StartTransaction())
using (var outputTrans = outputDb.TransactionManager.StartTransaction())
```

Nếu `outputTrans.Commit()` fail, `srcTrans` cũng sẽ abort. Điều này OK nhưng cần đảm bảo **thứ tự commit đúng** (output trước, source sau).

#### 🟡 Resource leak potential

`PlotSettings` objects được tạo và lưu trong `SourceFileInfo` nhưng disposal phụ thuộc vào `DisposePlotSettings` được gọi ở cuối. Nếu exception xảy ra trước đó, PlotSettings sẽ leak.

**Đề xuất**: Dùng `using` pattern hoặc đảm bảo disposal trong `finally`.

#### 🟡 File locking

```csharp
sourceDb.ReadDwgFile(source.Path, FileShare.ReadWrite, true, "");
```

Dùng `FileShare.ReadWrite` — nếu file đang được AutoCAD mở, có thể đọc được nhưng nội dung có thể inconsistent. Nên cân nhắc `FileShare.Read` nếu chỉ đọc.
